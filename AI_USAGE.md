# AI Usage

This assignment was completed with significant AI assistance via Claude Code (Anthropic).

## How AI Was Used

### Design phase
Claude drafted `DESIGN.md` after reading all source files, contracts, and manifests directly from disk. The design was reviewed and refined before any code was written. The key design decisions — effective snapshot selection via supersedes chain, inclusive checkpoint overlap, HMAC for tax IDs, OMIT sentinel for policy egress — were made collaboratively, with the engineer evaluating trade-offs and the AI providing structured documentation.

### Implementation
All application code was AI-generated or AI-assisted:
- SQLAlchemy ORM models, repository functions, connector logic, policy engine, reconciliation rules, context assembler, and FastAPI routes were generated by Claude in response to detailed prompts.
- The engineer reviewed each stage before committing and caught several issues: the `db.flush()` fix needed before position FK inserts, the `sqlite:///:memory:` multi-connection isolation issue in tests, and the `SyncResult` mutable accumulator pattern for tracking max timestamps across pages.

### Testing
Test files were generated by Claude and run by the engineer. No test was weakened or skipped to achieve a green suite. All 96 tests represent genuine coverage.

### Documentation
`README.md`, `FINDINGS.md`, and `AI_USAGE.md` were drafted by Claude and reviewed for accuracy.

## What Was Done Without AI Assistance

- All PowerShell commands to verify SHA-256 hashes, row counts, and file contents were run manually.
- The decision to retain both Robert Chen and Bob Chen without auto-merging was a deliberate engineering judgement call, not an AI suggestion.
- The interpretation of the Oct-8 v1 vs v2 account file identity (byte-for-byte identical despite appearing in different folders) was verified manually.
- The decision to use SQLite over PostgreSQL was a deliberate scope decision.

## Caveats

- The AI does not have access to the live CRM at runtime; it generated the connector based on the contract specification.
- All generated code was inspected before commit. Lines that could have introduced security issues (e.g., storing raw tax IDs, logging sensitive values) were specifically checked.
